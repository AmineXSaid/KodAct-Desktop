# Critique: the whole app (screenshots/light, screenshots/dark)

## Run 1 (2026-10-29)

Method: design review only (native platform). 139 screenshots from
`scripts`-style demo runs on Linux (Xvfb 1280×860, lavapipe, fallback fonts);
nothing seen on Windows.

Design specificity: the chat surface is Forge's own (activity lines, the
permission card, "Allowed by you · on this computer", mode chips); the chrome
around it (sidebar, composer, settings modal) is interchangeable with Claude
Desktop, and Forge's identity shows only in the cube and the accent.

Priority issues:
- P1: with the session panel and a side panel open at 1280px the transcript
  is ~140px wide: inline code breaks mid-word into empty chips, "main.r",
  the code block and the composer are clipped (light/100). Minimum transcript
  width; collapse the sidebar first, then overlay the session panel.
- P1: Forge's own copy names Claude / Claude Code as the reader (Rules and
  memory, Add an endpoint, Install skills). Forge/ForgeCLI is the subject;
  Claude Code only as compatibility.
- P2: primary buttons are black pills (New project, New rule, Check and save,
  Add server, Create) and accent (Allow, Send). DESIGN.md: primary = accent.
  Radius: DESIGN.md says 4px, buttons render as pills.
- P2: icon-only chrome and overloaded icons: folder = Files panel, project
  chip and title-bar files; plan = checklist in the title bar, route on its
  tab; ✦ opens the design-chat menu; only the selected panel tab has a label.
- P2: page headers on no shared scale (Projects/Rules ~34/18px, Design 22/15,
  Documents ~18/13, Settings 20/13); "off." orphan on Projects; uppercase
  KNOWLEDGE / MEMORY on the project page.

Minor: inline code is coral although DESIGN.md says neutral (decide, then
regenerate); the red-orange Rust file icon reads as a failure in "Edited 1

## Fixes (2026-10-29, after screenshots light and dark)

- Layout: the Session column now counts in the width the chat shares; when
  the panels' narrowest leave the chat under `chat_min`, the sidebar gives
  way to its rail (and comes back when they close), then the Session column
  floats over the chat. Inline code no longer leaves an empty chip at a line
  end: a glyph that starts a wrapped row was reported at the previous row's
  end (`WrappedLine::position_for_index`); the next glyph now places it.
- Copy: Rules and memory, Add an endpoint and Install skills name Forge as
  the reader; Claude Code only as compatibility. Endpoint name hint "Home
  Ollama". The sidebar's list is "Recents" in both states.
- Icons: the title bar's Plan toggle uses the panel's route icon; the side
  panel's chat-files tab is "Documents" with the sidebar's icon; the design
  chip reads "Design" with the sidebar's pen. The status bar says "Local".
- Type: Projects and Rules and memory take the page header the other pages
  use (20px semibold over a 14px muted lede). Knowledge and Memory use the
  section label (sentence case).
- Colour: inline code in the strong ink on its neutral wash; files in a list
  of changes show their kind in the muted ink. DESIGN.md and system.md
  regenerated, with the decision dated.
- Polish: the empty send arrow is the accent at 75% (it vanished in dark);
  a hovered sidebar row's title ends before its pin and menu; Design card
  descriptions clamp to two lines with an ellipsis; the project card's branch
  wraps to its own line instead of being cut.
- Not changed: page actions stay ink pills. The system's own decision ("Ink
  pills for the loud neutrals") keeps the accent for the one decision in
  front of you; the critique had read DESIGN.md's "button-primary" alone.
  DESIGN.md's Components now says so. Pills stay pills ("pills to press").
  The Lens keeps labels on the open tab only (its tooltips name the rest).

## Fixes from the Windows screenshots (2026-10-29)

- ASCII diagrams and aligned comments fell out of line: code was set in
  proportional Anthropic Sans. Code blocks, the terminal and paths now take
  the system's monospace (`fonts::MONO`: Consolas, Menlo, DejaVu Sans Mono),
  none bundled; the docs and the theme rule say so (the owner's call).
- A scroll bar showed in the message box for one line: its code-editor mode
  reserved half a viewport of empty rows under the last line. Those rows and
  the caret margin are off, and the box sizes from the editor's own line
  height and wrap width, so text stays inside it on every system.
- The queued message wrapped its own header and hid its actions. It now
  shows your words, then one line: "Waiting for Forge's next step", Send now,
  Edit, Remove. Send now (Ctrl+Shift+Enter, and in the palette) stops the
  reply and leaves the queue with ForgeCLI, which runs it as the next turn;
  the demo sends it afresh.
