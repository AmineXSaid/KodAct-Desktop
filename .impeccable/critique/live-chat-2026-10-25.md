# Live chat critique — 2026-10-25

Five screenshots from the user's Windows build (WSL remote, OmniRoute:
Gemma 4, Gemini 3 Flash, meta/muse-glimmer-30b). Each finding says what is
wrong, where it comes from in the code, and whose it is. "Engine" means
ForgeCLI or the gateway, not this app; Forge's own model proxy
(`src/model_proxy.rs`) passes request and reply bytes through unchanged.

## P0 — wrong or broken

1. **The last lines of a reply are washed out under the composer.**
   `workspace.rs` draws a permanent `edge_fade` gradient over the bottom of
   the transcript ("text running under it reads as there's more"). It is
   drawn even when the list follows the tail, and the last row has no
   bottom padding to clear it, so the newest streamed words and the working
   line sit in the fade ("Wait," in the Gemma shot). The fade should show
   only when scrolled away from the end, or the list needs a bottom
   inset ≥ `edge_fade`.

2. **A model's reasoning is printed as the answer.** Gemma and Gemini
   replies open with "The user said "hi". I should respond…" and run
   straight into the answer with no space ("naturally.Hi there!"). The
   transcript only makes a Thinking block from Anthropic-style `thinking`
   events (`backend.rs`); this reasoning arrives as plain text. The
   reasoning also quotes the system prompt back to the user ("The system
   instruction says 'You are Forge…'"). The 10-token count under a
   300-word reply shows the reasoning wasn't counted as output either.
   Whether the engine or OmniRoute folds it into the text can't be told
   from the screenshots; Forge should still not show it as the reply.

3. **The working line shows model debris.** "<thought>* Input:
   `<message>HI Gemma</message>`" is the headline side request
   (`title::headline`) answered by a model that echoed its thought tag and
   the prompt's `<message>` wrapper. `title::clean` strips only
   `<think>…</think>`, not `<thought>`, and takes the first non-empty line
   whatever it is. The same cleaner names chats, which is likely why the
   chat is still "Untitled 1" after five messages.

4. **The headline is about the wrong message.** The line reads "HI Gemma"
   while "whats my name ?" is being answered. A headline is asked per new
   turn; a message sent while a turn runs (a steer) keeps the old one.

5. **Sub-agents tell you nothing.** Six rows read "Using **agent** Find
   Rust files" for 6m 50s with "~6 tokens". The inline row is the generic
   tool line: verb "Using" + the tool name, no body while running, so it
   isn't even clickable. It doesn't show the agent's kind, its own time,
   how many steps it took, its latest step or words, or a way to stop that
   one agent, and it doesn't open the Agents panel that holds all of that
   (`AgentRun`: kind, prompt, steps, said, stop). After seven minutes and
   six tokens nothing says "this looks stuck" or offers to stop.

6. **A raw provider error is the whole explanation.** Gemini's 400 "Function
   call is missing a thought_signature…" is dumped as pretty-printed JSON
   with the proxy URL and token. Cause: Gemini 3 needs each tool call's
   thought signature sent back on the next request; the OpenAI-format route
   through the engine/OmniRoute drops it (Forge's proxy doesn't touch the
   body). The card should say that in one sentence, say this model can't
   use tools on this route, and offer to retry on another model. It shows
   none of that, and no Retry.

7. **Settings: the model list trapped the page** (the earlier report). The
   list kept every wheel tick even at its end, and Check and save sat
   below it. Fixed in this branch: the list hands the wheel to the page at
   its ends (`ui::hold_scroll`), and the form's actions are pinned under
   the page.

## Palette proposal (not applied — needs a yes)

The user's Forge Premium palette, mapped to existing tokens, background
unchanged:

| Role | Token today | Proposed |
| --- | --- | --- |
| Buttons, selected tab, focus | `primary` (rust/copper) | Electric Blue `#3B82F6` |
| AI agents, special highlights | — (agents use `primary`) | Royal Purple `#8B5CF6` |
| Running agents, live activity | spinner in `primary` | Teal `#14B8A6` |
| Done, success | `success` | Emerald `#22C55E` |
| Warning / error only | `warning` / `danger` | Amber `#F59E0B` / Coral `#EF4444` |
| Borders | `border` | Steel `#2A3446` |
| Text / secondary | `text` / `text_muted` | `#E6E9F0` / `#A3AED0` |

Contrast must pass `palette_check.rs`: `#3B82F6` on the dark canvas is
fine for fills and large text; white on `#3B82F6` is 3.7:1, under AA for
small button labels, so the button label would need `#0B0F1A` or a
darker blue (`#2563EB`, 5.2:1).

## Pass 2 — the details

16. **The reply's meta line floats 120px to the right.** "Took 3.7s ·
    10-token reply" starts well right of the reply's left edge (every
    reply in shots 13–15). The copy / like / dislike / retry icons that
    sit before it appear only on hover but keep their room, so at rest
    the line looks misplaced (shot 16 shows the icons that fill the gap).
    Either keep the icons visible and quiet, or let the text take their
    place at rest.
17. **Three colours for one "running" state in the agents group.** The
    group header's spinner is blue, each row's spinner orange, the
    working line's dots orange-brown. With the palette, running is Teal
    everywhere.
18. **The group header says "Using agent" for six agents**, singular, and
    each row repeats "Using **agent**": the words that differ (the task)
    are the faintest on the row, the words that repeat are the boldest.
    The bold "agent" is the tool's name styled as if it were a file.
19. **"~6 tokens" after 6m 50s** is shown as if it were progress. Six
    tokens in seven minutes means the model isn't answering; the line
    should say so (and offer Stop / switch model), not keep a calm
    shimmer.
20. **"WSL: Fedora" is a light chip on a dark bar** (shot 15, bottom-left):
    an inverted, near-white box in dark mode. It reads as a bug.
21. **The error tells you to "Open the model menu" but gives no button**
    for it; its only action is Copy. The action named in the text should
    be the button.
22. **The reasoning is rendered as Markdown** (the bullet list "User:
    'ola' …" in shot 13), so it looks like a deliberate, formatted answer.
23. **Reasoning glued to the reply** loses the space at the seam
    ("greeting.Hello!", "naturally.Hi there!") in every Gemma reply: the
    two parts arrive as one text run with no break.
24. **The scrollbar track shows at rest** along the whole transcript
    (shot 15, right edge), even when nothing scrolls past it.
25. **Forge knows your name** (account row "Kryptonite", "Welcome back")
    **but the model says it doesn't.** Not a bug; worth a setting to pass
    the name to the model.
26. **The stop button is a grey square on grey** (shots 13–15): the one
    action that matters while a turn runs has the lowest contrast in the
    composer. With the palette: Electric Blue ring, or Coral on hover.
27. **Settings (shot 12): an OmniRoute endpoint with "A gateway" off**, so
    its 33 models never reach the model menu; and rows show ids only
    ("glm-5.3", "gpt-5.5") with no names or chips, where the fake
    OmniRoute shows names. Whether that gateway sends names is unknown;
    the list should at least show the provider when the name is missing.
