KodAct

One mark, used once, on the right ground

A critique of how the desktop app uses the KodAct mark now, and an identity system that fixes it: one symbol with a short set of lockups, a rule for which ground each one sits on, a map of where it shows in the product, and three mockups.

What's wrong now

Native GPUI app, so this is a design review only (the web detector doesn't apply). Screenshots are from the app at a5723c4 on Xvfb in demo mode, light and dark. Sources: ui/mark.rs and every place that calls it.

P0

The mark is a status icon, so it shows up everywhere

The lime tile is drawn in the title bar, the home screen, the agents view header (32 px), every sidebar row for a chat that's working (12 px), every running sub-agent row, the live step of a work group, and the working line under the reply. In the demo session the screenshot shows two at once (title bar and working line). Each chat working in the background and each running sub-agent adds one more, animated: with two background chats and three sub-agents, that's seven tiles, six of them moving. A mark that's everywhere stops being a mark; it turns into wallpaper and competes with the reply.

Fix: one mark per screen. The brand appears at home and in the working line; everywhere else a running thing gets the ordinary running icon.

P0

In dark, the mark outshouts the reply

Lime #c6ff3d has a relative luminance of 0.84, while the reply's body ink #d9d7cf has 0.68. A filled square of the brightest colour in the palette is louder than any line of text. That breaks product principle 1, "the reply is the hero". Each extra tile in the sidebar and agent rows pulls the eye away from the words.

Fix: on ink, inside the product, draw the glyph (bar and triangle) in lime without the tile. It weighs about a third as much and still reads as KodAct.

P0

On paper, the tile has no edge

Lime tile #b5ea2c against the light canvas is 1.30:1, against the sidebar 1.16:1, and against a white Windows taskbar 1.18:1. The tile only shows up because of a hard 1 px olive offset shadow (mark_right), which is a zero-blur block shadow: the craft floor rules it out as a costume, and here it's patching an edge the colour doesn't have. The light-mode pixel wordmark is worse: its shadow is lime on paper (brand_shadow = #b5ea2c).

Fix: the tile always takes the opposite of its ground: an ink tile on paper, a lime tile on ink. No shadows in the desktop app.

P1

At 12–14 px the tile is a lime blob

At 12 px (sidebar rows) the cursor bar is 1.4 px wide and the triangle about 4 px: you can't make out either, so what's left is a bright square. At 14 px (work group, agent rows) it's barely better. The CLI's 16-pixel grid needs at least 16 px to read.

Fix: never draw the tile below 16 px. Below that, draw nothing brand-related; use the status icon.

P1

The mark means three different things

The same lime tile means "this app" in the title bar, "working" in the sidebar, and "a sub-agent" in a work group. The send button is a lime tile with the same run triangle, so the user's own action looks like the agent's status. Lime also already means "needs you" (the breathing dot).

Fix: assign meanings. The tile is the product (icon, About, onboarding). The glyph at work is KodAct acting, in one place: the working line. Send is a run triangle in a fill, with no cursor bar. Running elsewhere uses the neutral arc.

P2

On the pixel grid, the run triangle becomes a D

From 40 px up (PIXEL_FROM), the tile is drawn on the CLI's 16-pixel grid. Six columns can't hold a diagonal, so the triangle stair-steps into a rounded "D", and the mark loses the run-forward shape it's named for. In a terminal, half blocks force that grid. A desktop app can draw the real geometry.

Fix: draw the tile from its vector geometry at every size in the desktop app. Keep the pixels for the wordmark, where square letters are the material.

P2

The title bar repeats what the OS already shows

The Windows taskbar and Alt-Tab already show the app icon. Adding a tile beside the sidebar toggle makes a second brand mark on every screen, before the user has read anything. Claude Desktop, the product users compare this with every day, puts no mark in its chrome.

Fix: the title bar carries the name as type, "KodAct" in 13 px semibold, muted, with "Act" in the brand line. No tile.

The identity: one symbol, a few lockups

Claude's identity works because one shape, the spark, covers everything: it's the app icon in a tile, the symbol alone in the product, the lockup on the site, and it animates in exactly one place, while the model is writing. KodAct already has a shape that good: the cursor bar and the run triangle, "code, then act". The system keeps it and gives each use its own form.

Which ground takes which mark

The rule fits on one line: the tile is the opposite of its ground, and the mark's lime only ever touches ink.

Use Ink tile or ink glyph on paper. 17:1.
Use Lime tile or lime glyph on ink. 15:1.
Don't Lime tile on paper. 1.3:1, and only the hard shadow gives it an edge.
Don't Ink tile on ink inside the product; the edge disappears. (The app icon has its own keyline.)

The tile needs at least 16 px; below that, use the glyph (down to 12 px) or nothing. The desktop draws the tile from its geometry at every size: on the CLI's 16-pixel grid the triangle steps into a D (see the finding above), so the pixels stay with the wordmark. Clear space around any lockup is twice the cursor bar's width. Nothing else goes inside that space: no badge, no count, no dot.
