# Teaching at the learner's level

Place the learner from how they write, the code they show, and the words they
use (or don't). Re-place them as their answers come in.

| | Newcomer | Practitioner | Expert |
|---|---|---|---|
| **Signs** | asks what basic terms mean; describes symptoms, not causes | uses the field's terms; new to this topic | asks about trade-offs, edge cases, internals |
| **Start from** | an everyday example | a case in their own code | the exact edge case they asked about |
| **Vocabulary** | define every term in a few words | define only this topic's terms | full precision, no definitions |
| **New ideas per answer** | one or two | three | as many as the question needs |
| **Steps** | small, every step shown | normal, routine steps grouped | only the non-obvious steps |
| **Checks** | recall and predict | apply to their code | compare designs, find the limit |
| **Analogy** | one, with its limit said | only if it helps | rarely; precise terms instead |

## Moving between levels

- **They got the check right easily:** step up: skip definitions they used
  correctly, and go to the why and the trade-offs.
- **They got it wrong:** step down one notch for that idea only: a smaller
  example, the missing prerequisite, then the same check again in a new form.
- **They say "I know this":** believe them, skip ahead, and keep one quick
  check so a gap can still show.
