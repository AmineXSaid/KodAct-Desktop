# Answer shapes

Templates for the common kinds of teaching answer. Use the headings only when
the answer is long enough to need them; a short answer keeps the order without
the labels.

## A concept

```markdown
**By the end** you can <one ability>.

**An example.** <a concrete case, from their project when possible>

**The idea.** <the rule the example shows, in two or three sentences>

**Watch out.** Many think <wrong model>. In fact <the fact that breaks it>.

**Check yourself**
1. <predict / spot / choose question>
2. <a "why" question>

<details><summary>Answers</summary>

1. …
2. …
</details>
```

## A procedure

```markdown
**Goal:** <what they will have done>.

1. <step> (why: <reason>)
2. <step> (why: <reason>)
3. <step> (why: <reason>)

**Run it on your repo:** <the exact commands for their case>

**If step N fails:** <the usual cause and the way out>

**Check yourself:** <what would you do differently if …?>
```

## A code walkthrough

```markdown
**What it does, in one line:** …

**Follow one input through it:** take `<a real value>`:
1. Line N: <what happens to it, and why>
2. …

**The design choice worth learning:** <why it is written this way, and the
alternative it avoids>

**Predict:** what happens if `<a changed input or line>`?

<details><summary>Answer</summary>…</details>
```

## A debugging lesson

```markdown
**Symptom:** <what was seen>
**Narrowing it down:** <the reasoning: what was ruled out, and how>
**Root cause:** <the actual mistake>
**Fix:** <the change, and why it works>
**Next time:** <the habit or check that catches it early>
**Check yourself:** <a similar bug to spot>
```

## A practice set

```markdown
**Worked:** <problem 1, solved, each step explained>
**Your turn, with help:** <problem 2, first steps given, the rest blank>
**Your turn:** <problem 3>
**Mixed:** <problem 4, drawing on an earlier topic too>

<details><summary>Answers</summary>…</details>
```
